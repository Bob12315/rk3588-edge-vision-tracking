# 分阶段实施路线

## M0：仓库与接口基线（当前）

- [x] 固化状态机、安全仲裁和模型无关数据契约。
- [x] 提供模拟场景、单元测试和板端环境检查。
- [ ] 确认相机、镜头、云台、测距和 RK3588 板卡型号。
- [ ] 记录目标飞行高度、最小目标像素和端到端延迟预算。

退出标准：任何开发机可在无模型、无硬件条件下运行测试和模拟状态流。

## M1：电脑端视频基线

- [x] 接入文件视频源，记录帧时间戳与掉帧。
- [x] 接入 YOLO11n 人物检测，导出统一 `TargetObservation`。
- [x] 接入 YOLO-World V2，支持运行时文本类别并保留同视频对照。
- [x] 加入 12 色衣服分类与按 Track ID 的多帧稳定，避免复合提示忽略颜色属性。
- [x] 导出带框视频、逐帧 JSONL 和延迟统计。
- [x] 统一入口接入文件、RTSP 和 V4L2 摄像头索引。
- [ ] 为实时源建立只保留最新帧的有界队列，增加冻结和模型超时检测。
- 建立离线评估集，测量 precision、recall、mAP50、目标尺寸分桶结果。
- [x] 保存端到端吞吐和推理时延分位数，不只记录平均 FPS。

退出标准：录制视频可稳定复现检测结果，并形成第一份精度与时延报告。

## M2：持续跟踪与重捕获

- [x] 电脑端接入 ByteTrack，导出持续 `track_id` 和轨迹统计。
- [x] 加入持久单目标选择和状态机统一实时循环，超过丢失宽限后才允许切换 ID。
- [ ] 评估板端是每帧检测 + ByteTrack，还是“轻量单目标跟踪 + 周期检测”。
- 实现 0.5–2 秒周期重检和置信度下降触发重检。
- 建立遮挡、交叉、运动模糊、离画和再次出现测试集。

退出标准：目标 ID 切换率、重捕获耗时和失败样例可量化。

## M3：比赛数据与颜色验证

- 使用实际相机、实际高度、实际场地光照采集数据。
- [x] 先落地轻量框内颜色分类和时序稳定。
- [ ] 采集目标相机标注数据，训练 MobileNetV3 衣服颜色分类器并转换 RKNN。
- 保留大量无目标背景、相似干扰物和困难负样本。

退出标准：达到赛题定义的召回率和误报率门槛，门槛由团队在拿到规则后填写。

## M4：RK3588/RKNN 部署

- 记录 RKNN Toolkit、板端 Runtime、驱动和系统镜像的兼容矩阵。
- 用固定校准集完成量化，逐层对比 PyTorch/ONNX/RKNN 输出。
- 分别测量采集、预处理、NPU、后处理、跟踪和端到端延迟。
- 连续运行压力测试，记录温度、降频、内存和功耗。

退出标准：目标板长时间稳定运行，精度损失、温度和延迟均在已批准预算内。

## M5：飞控与安全闭环

- 使用 MAVLink 高级动作接口，禁止绕过 PX4/ArduPilot failsafe。
- 在 SITL 注入低电量、定位丢失、测距异常、视频冻结和模型超时。
- 明确人工接管优先级和通信心跳超时行为。

退出标准：故障矩阵全部通过后，才进入系留和低风险实飞。

## M6：开放目标与语义理解

- [x] 电脑端 YOLO-World 用于临时类别，并建立人物提示基线。
- [ ] 验证 YOLO-World 离线词汇 ONNX 导出与 RKNN 转换可行性。
- [x] 定义 VLM 画面目录、YOLO-World 提示词、属性/关系的结构化契约和回放入口。
- [x] 电脑端接入真实 Qwen3-VL-2B，用于目标描述结构化与 YOLO-World 提示词生成。
- [ ] 使用 Rockchip 官方视觉 RKNN + 语言 RKLLM 模型完成 RK3588 NPU 实机部署。
- 根据真实收益决定是否增加 MobileSAM。

退出标准：新增模型相对专用 YOLO 基线有可量化收益，且不破坏实时与安全预算。
