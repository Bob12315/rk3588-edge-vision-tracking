# 分阶段实施路线

## M0：仓库与接口基线（当前）

- [x] 固化状态机、安全仲裁和模型无关数据契约。
- [x] 提供模拟场景、单元测试和板端环境检查。
- [ ] 确认相机、镜头、云台、测距和 RK3588 板卡型号。
- [ ] 记录目标飞行高度、最小目标像素和端到端延迟预算。

退出标准：任何开发机可在无模型、无硬件条件下运行测试和模拟状态流。

## M1：电脑端视频基线

- 接入文件/RTSP/V4L2 视频源，记录帧时间戳与掉帧。
- 接入固定类别 YOLO，导出统一 `TargetObservation`。
- 建立离线评估集，测量 precision、recall、mAP50、目标尺寸分桶结果。
- 保存端到端时延分位数，不只记录平均 FPS。

退出标准：录制视频可稳定复现检测结果，并形成第一份精度与时延报告。

## M2：持续跟踪与重捕获

- 接入轻量单目标跟踪器；多人/多车场景再评估 ByteTrack/BoT-SORT 与 Re-ID。
- 实现 0.5–2 秒周期重检和置信度下降触发重检。
- 建立遮挡、交叉、运动模糊、离画和再次出现测试集。

退出标准：目标 ID 切换率、重捕获耗时和失败样例可量化。

## M3：比赛数据与颜色验证

- 使用实际相机、实际高度、实际场地光照采集数据。
- 固定目标训练专用 YOLO；颜色相近目标增加框内 HSV/小分类器复核。
- 保留大量无目标背景、相似干扰物和困难负样本。

退出标准：达到赛题定义的召回率和误报率门槛，门槛由团队在拿到规则后填写。

## M4：RK3588/RKNN 部署

- 记录 RKNN Toolkit、板端 Runtime、驱动和系统镜像的兼容矩阵。
- 用固定校准集完成量化，逐层对比 PyTorch/ONNX/RKNN 输出。
- 分别测量采集、预处理、NPU、后处理、跟踪和端到端延迟。
- 连续运行压力测试，记录温度、降频、内存和功耗。

退出标准：目标板长时间稳定运行，精度损失、温度和延迟均在已批准预算内。

## M5：飞控与安全闭环

- 使用 MAVLink 高级动作接口，禁止绕过 PX4/ArduPilot failsafe。
- 在 SITL 注入低电量、定位丢失、测距异常、视频冻结和模型超时。
- 明确人工接管优先级和通信心跳超时行为。

退出标准：故障矩阵全部通过后，才进入系留和低风险实飞。

## M6：开放目标与语义理解

- YOLO-World 用于临时类别和丢失重捕获。
- 1B–3B 轻量 VLM 用于目标描述结构化与多候选消歧。
- 根据真实收益决定是否增加 MobileSAM。

退出标准：新增模型相对专用 YOLO 基线有可量化收益，且不破坏实时与安全预算。
