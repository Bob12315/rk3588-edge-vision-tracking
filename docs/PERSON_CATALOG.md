# 逐人物扫描、属性目录与指定人物跟踪

## 网页流程

连接 USB 摄像头或上传视频后，点击“扫描并选择人物”：

```text
YOLO-World(person) + 用户选定跟踪器连续扫描 18 帧
                    ↓
仅保留至少出现 3 帧的稳定 Track ID
                    ↓
每个 Track 保留置信度和可见面积更好的裁剪图
                    ↓
Qwen3-VL 逐张输出受控 JSON 属性
                    ↓
网页显示最多 6 张英文人物卡片
                    ↓
用户点击 TRACK THIS PERSON
                    ↓
继续原跟踪会话，只输出选中的 Track ID
```

扫描视频时不会回到第 0 帧重新建跟踪器：卡片生成后从第 19 帧继续，因此扫描
Track ID 与后续跟踪 ID 属于同一个 ByteTrack 或 BoT-SORT 会话。分析期间画面暂停，避免 VLM
耗时导致视频位置或跟踪状态悄悄前进。

## 受控属性

VLM 只能从固定英文枚举中选择，无法生成“dark reddish casual clothes”等自由描述。
当前目录包含：

- 上衣颜色和类型。
- 下装颜色和类型。
- 帽子或头盔及其颜色。
- 背包、手提包或雨伞及其颜色。
- 安全背心。
- standing、walking、running、riding 等当前动作。
- 上身、下身和头部可见程度。

看不清时必须返回 `unknown`。程序根据同一次扫描中其他卡片的属性，选择最短的
一至两个差异属性作为推荐标签。`unique_in_scan` 只表示当前扫描内可区分，不代表
跨场景身份唯一。

## 安全边界

- 人物框和 Track ID 始终来自 YOLO-World 与所选跟踪器，不由 VLM 生成。
- VLM 属性用于场景目录和人工选择，不被当作逐帧颜色真值。
- 选择具体人物后，只锁定该 Track ID；目标丢失时不会自动切换到画面中另一个人。
- 网页可选 BoT-SORT + ReID 身份增强；它只是辅助关联，不保证长时离画重入后仍为
  原 ID。不确定时应重新扫描。详见[身份增强跟踪](IDENTITY_TRACKING.md)。
- USB 摄像头在人物分析期间冻结读取；若人物已明显移动，建议重新扫描后再选择。
- “检测所有同类属性的人”仍走现有 `person + 独立颜色复核` 链路，不把复合衣着句子
  当作 YOLO-World 的可靠最终判断。

## 本机视频验证

在 `04fc81fbf08451011829cc6a084fad27.mp4` 的 384 实时档中：

- 18 帧扫描得到 2 个稳定人物，每个都有 18 个轨迹样本。
- 两张人物裁剪的 Qwen3-VL 结构化分析完成，最后一次调用约 3.34 秒。
- 骑手卡片为 `orange t-shirt / black pants / riding`；另一张卡片为
  `blue t-shirt / gray jeans / black hat / standing`。
- 选择骑手后处理到第 1722 帧，累计 1347 个匹配帧且只输出 Track ID 2，处理速度
  约 26.80 FPS；目标离开画面后状态为 `lost`，没有切换到其他人物。

骑手衣服在不同光照下跨越棕色和铁锈橙，因此卡片中的 `orange` 不能替代现有的棕色
ROI复核。这正是“VLM负责列目录，确定性模块负责最终属性判断”的预期分工。
