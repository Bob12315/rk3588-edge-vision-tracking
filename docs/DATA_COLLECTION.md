# 数据采集与评估准备

## 场景覆盖

- 不同高度、距离、俯仰角、目标朝向，以及画面中心和边缘。
- 晴天、阴天、阴影、逆光、不同曝光与白平衡。
- 部分遮挡、完全短时遮挡、运动模糊、相似颜色背景。
- 多个相同形状不同颜色的目标同时出现。
- 大量无目标背景、相似干扰物和容易误检的困难负样本。

## 数据分割

训练、验证、测试应按飞行架次或场景分割，不能把同一段视频的相邻帧随机分到不同集合，否则指标会因画面高度相似而虚高。测试集必须保留一部分从未参与调参的场地、光照或架次。

## 标注字段

- 固定类别与 `xyxy` 框。
- 颜色属性；外形相同的桶类优先统一检测“桶”，颜色单独评估。
- 遮挡、截断、模糊、小目标和困难样本标记。
- 需要多目标跟踪时增加跨帧 `track_id`。
- 关系目标增加主体、客体和关系，例如 `person --carrying--> blue_box`。

## 最低评估集

- 检测：precision、recall、mAP50，并按目标像素尺寸和高度分桶。
- 跟踪：ID 切换、跟踪成功率、丢失后重捕获耗时。
- 性能：端到端延迟 P50/P95/P99、有效 FPS、掉帧率。
- 稳定性：连续运行时长、峰值内存、温度、降频与功耗。
- 安全：低电量、定位丢失、近障、视频冻结和模型超时的结果。

原始视频、数据集和模型权重默认不提交 Git。发布前应检查画面隐私、许可和比赛数据使用条款。
